1. Overview & Tech Stack

Quizora is a past-questions learning platform where students prepare for external examinations (BECE now, WASSCE later) by solving past questions with timers, analytics and institutional monitoring. This backend implements Phase 1 (MVP): authentication, courses, a question bank, a quiz engine, subscriptions, institutional licensing and reporting.

Maven Wrapper — pins Maven 3.9.x and downloads it on first use, so any machine with a JDK can build with ./mvnw test or ./mvnw spring-boot:run without installing Maven.

One-command PostgreSQL 16 for production-like local runs: exposes port 5432, database quizora, user/password postgres/postgres, a named volume for data persistence. Usage: docker compose up -d then ./mvnw spring-boot:run.

src/main/resources/application.yml CONFIG

Default profile configuration:

  • Datasource — PostgreSQL via env vars DB_URL/DB_USER/DB_PASSWORD (sensible localhost defaults).
  • JPA — ddl-auto: update (schema auto-sync for development; swap to Flyway/Liquibase before production), open-in-view: false, UTC timezone, ISO date serialization.
  • quizora.security.jwt — HS256 secret from JWT_SECRET (dev fallback ≥32 chars), token lifetime 24 h.
  • quizora.cors.allowed-origins — from CORS_ORIGINS, default *.
  • quizora.seed.enabled=true — toggles DataSeeder; quizora.subscription.trial-days=7 — free trial length.

src/main/resources/application-demo.yml CONFIG

The zero-setup demo profile: swaps the datasource to in-memory H2 in PostgreSQL compatibility mode (MODE=PostgreSQL), create-drop schema, enables the H2 web console. Every run starts fresh and re-seeds demo data — ideal for local exploration and for the integration tests.

4. config/ — Security & Seed Data

SecurityConfig.java SECURITY

The heart of the security setup (@Configuration @EnableWebSecurity @EnableMethodSecurity). Three beans:

filterChain(HttpSecurity)

  • Stateless sessions (no cookies — JWT only), CSRF disabled (not needed for token auth).
  • Route rules: /api/auth/**, /actuator/health, /h2-console/** and all OPTIONS preflights are public; /api/admin/** requires role ADMIN; everything else requires authentication.
  • Inserts JwtAuthenticationFilter before Spring's username/password filter.
  • Custom JSON 401/403 bodies (never HTML error pages), frame-options sameOrigin so the H2 console works.

corsConfigurationSource()

Origins from quizora.cors.allowed-origins (comma-separated), all standard methods/headers allowed. allowCredentials=false deliberately — JWT rides in the Authorization header, and Spring rejects wildcard origins combined with credentials.

passwordEncoder()

BCrypt — all stored passwords are salted hashes; plaintext never persisted.

DataSeeder.java SEED 239 lines

A CommandLineRunner that runs on startup when quizora.seed.enabled=true (and only if the data is absent — safe to re-run). Four phases:

  1. seedUsers() — platform admin, demo student (yearly subscription pre-activated), institution admin and an institution student.
  2. seedQuotes() — 12 motivational quotes that power the daily dashboard quote.
  3. seedCoursesAndQuestions() — 6 JHS subjects (Integrated Science, Maths, English, Social Studies, Creative Arts, Ghanaian Language) with 44 BECE-style objective questions across the 2023 & 2024 papers — each with 4 options, a correct answer and an explanation.
  4. seedInstitution() — "Demo JHS Accra" plus licence code DEMO-CODE-1234 (20 seats, valid 2026-01-01 → 2027-12-31).

5. security/ — JWT Authentication

How a request is authenticated, step by step:

1. Client logs in  ──► AuthService verifies BCrypt hash
2. JwtService.generateToken(user) signs HS256 JWT (id + email + role, 24 h)
3. Client sends     Authorization: Bearer <token>   on every request
4. JwtAuthenticationFilter parses & verifies the token
5. QuizoraUserDetails placed in SecurityContext  →  @CurrentUser injects User

JwtService.java SECURITY

  • generateToken(User) — signs a JWT with subject=email, claims uid & role, 24 h expiry (configurable expiration-ms).
  • parse(String) — verifies signature + expiry and returns the claims (throws on invalid tokens).
  • getExpirationMs() — surfaced to clients so they can show token lifetime / schedule refresh.

JwtAuthenticationFilter.java SECURITY

A OncePerRequestFilter that runs before authorization. Reads the Authorization: Bearer … header, parses the token, loads the user via QuizoraUserDetailsService, and — only if the user isn't already in the SecurityContext — sets the authentication. Malformed/expired tokens are silently ignored so the request falls through to the 401 entry point.

QuizoraUserDetails.java SECURITY

Implements Spring's UserDetails: wraps the DB user as id, role, email (username), password hash. Authorities are derived from the role (ROLE_STUDENT / ROLE_INSTITUTION_ADMIN / ROLE_ADMIN), which is what makes hasRole("ADMIN") work.

QuizoraUserDetailsService.java SECURITY

Bridges Spring Security to the UserRepository: loadUserByUsername(email) (used by the filter; case-insensitive lookup with join-fetch of the institution to avoid lazy-init issues) and loadByEmail for internal use. Throws UsernameNotFoundException when unknown.

CurrentUser.java SECURITY

A small helper injected into controllers/services: get() returns the authenticated User or throws 401/403; find() returns Optional. Backed by UserRepository.findWithInstitution (join fetch) so lazy relationships are already loaded.

6. domain/ — Entities & Enums (17 files)

Entities (9)

User.java ENTITY

Account record: id, email (unique, case-insensitive), passwordHash (BCrypt), fullName, role (enum), optional institution and the licenseCode used to join one. Every quiz, subscription and seat belongs to a user.

Institution.java ENTITY

A school/organisation: name, contactName, contactEmail, phone. Owns licence codes and its students; powers the institutional portal and reports.

LicenseCode.java ENTITY

Bulk-seat licence: unique code (format QZRA-XXXX-XXXX), parent institution, totalSeats/usedSeats, validity window validFrom→validUntil, status (LicenseStatus). A student "consumes" one seat when registering with the code.

Subscription.java ENTITY

Access grant for one user: plan (MONTHLY/YEARLY/TRIAL — PlanType), startDate, endDate, paymentRef (mock MOCK-PAY-… today), status (SubscriptionStatus). Expiry is checked lazily on read and swept nightly.

Course.java ENTITY

A subject/paper: name ("Integrated Science"), unique code ("SCIENCE"), description, level (JHS/SHS — Level enum, SHS reserved for Phase 3), createdAt. Parent of all its questions.

Question.java ENTITY

A past question: course, examYear (column is exam_year because year is a reserved word in H2/SQL), section (OBJECTIVE now / SUBJECTIVE in Phase 2), questionText, four options optionA–D, correctOption (AnswerOption enum), explanation shown after submission, marks (default 1), createdAt. Helper optionAt(answer) resolves an option letter to its text. Indexed on (course_id, exam_year).

QuizAttempt.java ENTITY

One sitting of a paper: user, course, exam_year, timed flag + timeLimitSeconds (server-authoritative clock), status (AttemptStatus: IN_PROGRESS → SUBMITTED/EXPIRED), startedAt/submittedAt, results totalQuestions, answeredCount, correctCount, scorePercent, durationSeconds. Domain logic lives on the entity: expiresAt() computes the deadline and isExpiredNow() tells the service when to auto-grade.

AttemptAnswer.java ENTITY

One saved answer inside an attempt: link to attempt + question, the selectedOption, whether it was correct, and timeSpentSeconds. Rows are written as the student answers (so an expiry still captures partial work), then graded results are computed on submit.

MotivationalQuote.java ENTITY

Simple text + author row; 12 seeded quotes rotated deterministically once per day for the dashboard.

8. dto/ — Request/Response Contracts (8 files)

9. exception/ — Error Handling (6 files)

Services throw typed exceptions; one @RestControllerAdvice turns them into a uniform JSON body:

{ "status": 404, "error": "Not Found",
  "message": "Course not found: 99", "path": "/api/courses/99",
  "timestamp": "2026-10-02T10:30:00" }

ApiException.java BASE

Base runtime exception carrying an HTTP HttpStatus + message — the common parent for all typed errors below.

NotFoundException.java 404

Resource doesn't exist (e.g. "Question not found: 12").

BadRequestException.java 400

Semantically invalid input (e.g. answering a question that isn't in the attempt).

ForbiddenException.java 403

Authenticated but not allowed (e.g. an institution admin touching another school's data).

ConflictException.java 409

Duplicate resource (e.g. email already registered, duplicate course code).

GlobalExceptionHandler.java ADVICE

Maps every failure path to the JSON shape above: ApiException → its status; MethodArgumentNotValidException → 400 with each field message joined ("email: must be a valid email; …"); BadCredentialsException → 401 "Invalid email or password" (never reveals which half was wrong); AccessDeniedException → 403; any other Exception → 500 with a safe message.

10. service/ — Business Logic (11 files)

Services hold all business rules and are the transaction boundary (@Transactional on writes, @Transactional(readOnly = true) on reads — which also fixes lazy-loading and enables Hibernate read optimizations). Controllers stay thin; repositories never leak upward.

AuthService.java SERVICE

Everything about accounts and sign-in.

  • register() — individual sign-up: validates uniqueness (case-insensitive email), BCrypt-hashes the password, creates the user, and grants a 7-day free trial via SubscriptionService.createTrial(); returns JWT + profile.
  • registerInstitutional() — same flow but requires a valid licence code (requireUsableLicense: exists, active, seats left, within validity window), links the institution, and consumes one seat; grants an institutional (licence-backed) subscription.
  • login() — verifies credentials (401 on bad password), returns token response.
  • joinCode() — lets an existing student link their account to an institution later with a licence code.
  • toUserDto() — builds the profile DTO (incl. subscription with daysRemaining).

SubscriptionService.java SERVICE

Access control & the subscription lifecycle — the future Paystack/MoMo integration point.

  • requireActive(user) — gate called before starting a quiz; throws 403 when there is no active subscription.
  • createTrial() — 7 days from today (quizora.subscription.trial-days).
  • createInstitutional() — subscription spanning the licence's validity window.
  • activate(user, plan, days, paymentRef) — activates MONTHLY (30 d) / YEARLY (365 d) with a mock payment ref (MOCK-PAY-…); if an active sub exists, the new period extends from the current end date (never shortens what the user already paid for).
  • lazyExpire() — flips a stale row to EXPIRED whenever it's read.
  • expireEndedSubscriptions() — @Scheduled(cron "0 0 3 * * *") nightly sweep at 03:00 marking all ended subscriptions EXPIRED.
Swapping in real payments later: keep this service's lifecycle; replace the mock activate() call with a Paystack/MoMo webhook that invokes the same method with the real transaction reference.

CourseService.java SERVICE

Read side of the courses module: list() (every subject with its questionCount and available exam years), get(id) detail, years(id) — per-year question counts so the UI can enable/disable year buttons, and requireCourse() used by quiz/admin flows (404 if missing).

QuizService.java SERVICE largest service — the quiz engine

Implements the exam experience end-to-end with server-authoritative timing and grading (a client can never see or fake the correct answer or the clock).

  • start() — checks subscription, loads the paper's questions for (course, year), creates a QuizAttempt (optionally timed) and returns metadata: attempt id, total questions, expiresAt.
  • question(attemptId, index) — serves one question at a time: text + four options + the student's saved answer + remainingSeconds. Ownership check (requireOwned) and in-progress check; never includes correctOption. If the clock has run out it auto-submits first.
  • answer() — saves/overwrites the selected option with time spent (upsert by question).
  • submit() — idempotent: grades all answers server-side, computes counts/score/duration, marks status SUBMITTED (or EXPIRED if the timer elapsed), and returns the full result.
  • result() — the graded paper: totals, score percent, and a review list with the correct option + explanation per question.
  • history() — paginated past attempts.
  • Privates: requireOwned, requireInProgress, finalizeAttempt (grading), buildResult, remainingSeconds.

DashboardService.java SERVICE

Powers the student home screen in one call (dashboard(user)): time-of-day greeting, profile, the daily quote, analytics (courses attempted, questions attempted, accuracy %, average score, total time, study streak — consecutive days with at least one attempt, computed by streakDays()), and the current subscription summary.

ProgressService.java SERVICE

Analytics behind the Progress page (all read-only transactions):

  • progress() — overall TotalsDto (attempts, questions, accuracy, time spent), per-course breakdown, a daily trend (buildTrend(): attempts + average score per day for the graph), and recent attempts.
  • attemptHistory() — paginated attempt list.

QuoteService.java SERVICE

todayQuote() — deterministic daily rotation: index = days-since-epoch mod quote count, so every client sees the same quote for a whole 24 h window with no per-request randomness. Falls back to a built-in quote if the table is empty. validUntil tells clients when it changes.

InstitutionService.java SERVICE

The institutional (B2B) side:

  • create() — platform admin creates an institution + its admin account in one step.
  • get() — overview with licence codes and seat usage (after requireInstitutionAccess(): only that institution's admin or a platform admin).
  • createLicense() — generates a unique QZRA-XXXX-XXXX code (generateCode()/randomBlock() with collision retry) for N seats within a validity window.
  • students() — per-student snapshots (attempts, accuracy, average score, last active, subscription status) built by buildStudents(), which filters to Role.STUDENT so the institution's own admin is excluded from their report.
  • summary() — reporting-dashboard aggregates: totals, 30-day active students, accuracy, seats used/total.

ReportService.java SERVICE

Builds downloadable institution reports as byte[]:

  • toCsv() — header row + one row per student (name, email, attempts, questions, accuracy, average score, last active, subscription), RFC-4180 escaping for commas/quotes.
  • toPdf() — OpenPDF document with a styled header (institution name, date) and a table of the same columns using cell() helpers.

Both enforce requireInstitutionAccess() first — a school can only export its own data.

AdminService.java SERVICE

Back-office operations for the platform admin:

  • stats() — dashboard counts: users, students, institution admins, institutions, courses, questions, attempts.
  • createCourse() / createQuestion() — single additions with uniqueness validation (409 on duplicate course code).
  • createQuestionsBulk() — bulk paper upload: a whole year's questions in one JSON payload; returns how many were created.
  • listQuestions(courseId?, year?) — optional filters; includes correct answers (admin-only endpoint).
  • deleteQuestion(), listUsers(role?).
  • activateSubscription() — manual activation/extension for a user (support tool, same extension semantics as self-service).
